# Refusal codes

Every reason code the pre-tool hook can refuse with, and the landing refusals
of `compass ship-commit` and `compass quick-fix finish` (`checkpoint-no-outcome`,
and `release-line-missing` and `release-line-heading`, which `docs/release-line.md`
describes), generated from `cli/compass_pkg/refusals.py` by `compass _refusal --list`. Do not
hand-edit the list below - regenerate it after any change to the registry,
and `tests/test_refusal_registry.py` fails the build if it goes stale.

A refusal always has three lines - `Blocked:`, `Why:`, `Fix:` - and ends
with its code in brackets, e.g. `[no-red-on-record]`. Search this page for a
code from a refusal you hit.

### `approval-request-protected`

**Blocked:** {target} (tool: {tool})
**Why:** approval requests and the approval hook belong to Compass; an approval binds to the request a person was shown.
**Fix:** ask for an approval with compass evidence request, then ask the person to type /compass:approve.

### `artifact-rule-not-applied`

**Blocked:** landing of issue '{slug}'
**Why:** {documents} is on disk, so {rules} applies, but the recorded approach was evaluated before the document was there.
**Fix:** run compass approach evaluate --issue {slug} --write, pass any gate it adds, then ship again.

### `bad-current-task`

**Blocked:** this edit
**Why:** '.compass/current-task' names '{slug}', which is not one path segment - a slug names a directory directly under .compass/work/.
**Fix:** fix .compass/current-task to name a real issue slug, then retry.

### `bad-session-issue`

**Blocked:** this edit
**Why:** COMPASS_ISSUE names '{slug}', which is not an issue directly under .compass/work/. It names this session's issue ahead of .compass/current-task, so the edit is not judged by another issue instead.
**Fix:** set COMPASS_ISSUE to a real issue slug, or unset it to use .compass/current-task, then retry.

### `checkpoint-no-outcome`

**Blocked:** landing of issue '{slug}'
**Why:** {stages} {is} listed in checkpoints with no outcome recorded, so nothing shows a person answered {it}.
**Fix:** the person who answers runs compass evidence approve --checkpoint {stage} --approver <you> --role <role>, for each stage named, then ship again.

### `config-invalid`

**Blocked:** edit to {target} (tool: {tool})
**Why:** '{file}' could not be read: {detail}
**Fix:** fix {file} and retry.

### `delegation-caller-mismatch`

**Blocked:** delegated approval (--as {named})
**Why:** Claude Code reports this call as {caller}, and a delegated approval must name exactly the agent that makes it. A word the shell could build is refused too.
**Fix:** run it from the agent the delegation names, with --as set to that agent's full name, or ask with compass evidence request.

### `delegation-protected`

**Blocked:** {target} (tool: {tool})
**Why:** a delegation is a person's decision, written only from a typed /compass:delegate, and its folder holds the check for the code that confirms one.
**Fix:** ask the person to type /compass:delegate or /compass:revoke; never read or write a delegation file yourself.

### `no-acceptance-criteria`

**Blocked:** edit to {target} (tool: {tool})
**Why:** the acceptance-before-code guardrail blocks this: define: thorough is set but manifest.yml has no scenarios.
**Fix:** add the scenarios to acceptance-criteria.md and manifest.yml (compass scenario add), or run /compass:assess --reassess if this is exploratory.

### `no-delivery-approach`

**Blocked:** this edit
**Why:** issue '{slug}' has no delivery-approach.md - its assessment did not finish.
**Fix:** run /compass:assess.

### `no-red-on-record`

**Blocked:** edit to {target} (tool: {tool}, guarded by {guard})
**Why:** no failing test is on record for issue '{slug}' - the red-before-green strategy applies here.
**Fix:** run compass tdd-red --scenario <id> -- <your failing test command>, then retry this edit.

### `not-initialised`

**Blocked:** this edit
**Why:** no issue has been assessed yet - {detail}.
**Fix:** run /compass:assess before changing code, or /compass:quick-fix for a small, low-risk change.

### `pointer-moved`

**Blocked:** this edit
**Why:** another session moved .compass/current-task from this session's issue '{previous}' to '{slug}', so this edit would count against the wrong issue.
**Fix:** in this session, run `compass issue use {previous}` to carry on, or `compass issue use {slug}` to switch, then retry.

**Blocked:** edit to {target} (tool: {tool})
**Why:** python3 was not found on the PATH, so Compass cannot check whether this edit is allowed.
**Fix:** install python3 (3.10+) or put it on PATH, then retry.

### `reader-failed`

**Blocked:** this edit

### `red-unsigned`

**Blocked:** this edit
**Why:** the red record for issue '{slug}' carries no identity - no content_digest - and this project needs one for records written since records_signed_since: {since_date}.
**Fix:** run compass tdd-red --scenario <id> -- <your failing test command>.

### `release-line-heading`

**Blocked:** the release line of issue '{slug}'
**Why:** it starts with #, and the living spec reads a line such as ### <slug> (completed <date>) as one of its issue headings.
**Fix:** write the release line as plain text that does not start with #, then run the command again.

### `release-line-missing`

**Blocked:** landing of issue '{slug}'
**Why:** issue '{slug}' has no release line, and its approach owes one: a sentence for users that the release notes list.
**Fix:** give it with --release-note "<text written for a user>", then run the command again.

### `settings-conflict`

**Blocked:** edit to {target} (tool: {tool})
**Why:** .compass/config.yml sets {keys}, but compass.yml is read, so those keys guard nothing.
**Fix:** Move them into compass.yml (write mode as adoption) and delete them from .compass/config.yml, then retry.

### `transcript-protected`

**Blocked:** {target} (tool: {tool})
**Why:** the session transcript holds what Compass showed only to the person, such as the code that confirms a delegation.
**Fix:** work from the conversation and the files in the project; ask the person for anything you need from the transcript.

### `waits-for-issue`

**Blocked:** edit to {target} (tool: {tool})
**Why:** issue '{slug}' waits for {dependency} to reach {until}{more}, and this checkout reads {dependency} as {state}.
**Fix:** if {dependency} is finished in another checkout, bring its .compass/work/{dependency}/ folder here; or run compass issue depends remove {dependency}.
